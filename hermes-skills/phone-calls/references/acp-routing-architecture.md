# ACP Routing Architecture — Dual-Brain PTT System

## Overview

The callbridge `control_server.py` implements a **dual-brain routing** system for the push-to-talk (PTT) feature. Two separate "brains" are created at startup, each routed to different hotkeys:

| Hotkey | Brain | Backend | Tools/Skills |
|--------|-------|---------|-------------|
| Shift+F1 (half-duplex) | `brain_full` | ACP (`hermes acp` via stdio) | ✅ All tools, skills, memory |
| Shift+F2 (full-duplex) | `brain_full` | ACP (`hermes acp` via stdio) | ✅ All tools, skills, memory |
| Shift+F3 (limited) | `brain_limited` | HermesClient → phone server :8780 | ❌ No tools, basic web search only |

External phone calls (GSM/Android) use the phone server directly via `transport.py` router — **no Hermes tools**.

## Architecture Principle

**User-facing interfaces (PTT, Android app) → Full agent with tools**
**External calls (phone to strangers) → Limited brain without tools**

The phone server exists to complete delegated tasks (e.g., "call the restaurant and book a table"). The person on the other end should NOT have access to Hermes tools. The user (via PTT or app) gets the full agent.

## Implementation in control_server.py

```python
# In run_server() — PTT brain creation
from .acp_client import AcpAgentClient

if config.acp_enabled:
    brain_full = AcpAgentClient(config)  # Full agent via ACP/stdio
else:
    brain_full = bridge.hermes  # Fallback to HermesClient (phone server)

brain_limited = bridge.hermes if isinstance(bridge.hermes, HermesClient) else StubHermes()

# Warm-up ACP in background (non-blocking)
if isinstance(brain_full, AcpAgentClient):
    threading.Thread(target=brain_full.warm_up, daemon=True).start()

PushToTalkManager(config, brain_full, brain_limited).start()
```

## ACP (Agent Client Protocol)

- **Protocol**: JSON-RPC newline-delimited over stdio
- **Command**: `wsl.exe -d Ubuntu -- bash -lc "cd /home/ataini && exec python -m hermes_cli.main acp --accept-hooks"`
- **Flow**: `initialize` → `session/new` → `session/prompt` (repeated)
- **Response chunks**: `agent_message_chunk` updates carry streaming text
- **Reverse requests**: `session/request_permission` auto-approved, `fs/*` and `terminal/*` declined

## ACP Client (acp_client.py)

The `AcpAgentClient` class:
- Launches `hermes acp` as a subprocess in WSL
- Maintains persistent session (context preserved across prompts)
- Has cooldown mechanism (30s) after failed starts
- `respond(text, preamble=None)` → yields text chunks
- `warm_up()` → pre-starts the agent (best-effort, may fail in NSSM Session 0)

## ACP Voice Preamble

The `acp_voice_preamble` config string is prepended to every prompt sent to the ACP agent:

```
[Contesto: stai parlando a voce con l'utente tramite un sistema esterno 
che converte il tuo TESTO in audio. Rispondi SOLO con testo da leggere 
ad alta voce, in modo breve e naturale. NON usare strumenti di sintesi 
vocale/TTS.]
```

This prevents the agent from trying to use TTS tools (audio is generated by Handy/Kokoro, not the agent).

## Config Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `acp_enabled` | `true` | **MUST be true** for tools in PTT |
| `acp_wsl_distro` | `"Ubuntu"` | WSL distro for `wsl.exe -d` |
| `acp_wsl_command` | (see config.py) | Command to launch `hermes acp` |
| `acp_cwd` | `/home/ataini` | Working directory for session |
| `acp_init_timeout_s` | `240.0` | Timeout for ACP initialization |
| `acp_response_timeout_s` | `300.0` | Max wait for agent response |
| `acp_voice_preamble` | (see above) | Instruction prepended to every prompt |

## Known Issues

### NSSM Session 0 ACP startup failure
The ACP warm-up thread often fails when the service starts via NSSM (Windows Session 0, non-interactive). Error: `ACP: avvio agente fallito: ACP initialize fallito/timeout`. This is non-blocking — the ACP starts lazily on the first Shift+F1 press.

### First-press latency
First Shift+F1 press after service restart requires ~90s for ACP to initialize (loading tools, MCP servers). Subsequent prompts are instant.
